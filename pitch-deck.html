The Problem · PS1

Insiders already hold the keys.
Normal security never sees them.

The threat is inside

Employees, contractors, vendors and admins — acting maliciously, negligently, or under compromise — already have privileged access to core banking systems.

Perimeter defences miss it

They use legitimate credentials. Firewalls, EDR and login-time MFA don't flag a trusted user quietly abusing the access they're supposed to have.

Lost in the noise

One malicious action hides among thousands of normal privileged operations. By the time anyone notices, the data — or the money — is already gone.

Why we chose PS1

Attack-first advantage

Our team's edge is offensive security. We know exactly how insiders abuse privileged access — so we detect it attack-first, grounded in real techniques, not guessed at with a black-box model. It's also the most defensible problem for a security team versus a crowded fraud-ML field.

Pre-Requisites

What the solution needs to run.

  • Privileged-session telemetry — logons (time / geo / device), commands, DB queries, file access, privilege escalation, account & ACL changes.
  • Identity & asset inventory — privileged users, roles, and which systems are crown-jewels.
  • Behavioural baselines — per-identity history, or the CMU CERT Insider Threat dataset (r4.2 / r5.2) for training & validation.
  • Inline deployment — the tool sits as a broker in the privileged-access path (SSH / RDP / DB proxy).

Assumptions

  • Python 3.11+ runtime.
  • Runs fully on-prem — no external SaaS.
  • Data never leaves the bank.
  • Deploys alongside existing PAM / SIEM.

Security Considerations

Security is the product — including post-quantum.

  • Zero credential exposure — secrets are brokered via injection; users never see them.
  • Least-privilege, risk-based access — automatic session kill on critical risk.
  • Aligned to standards — RBI Cyber Security Framework, MITRE ATT&CK, NIST PQC.

Post-quantum by design

  • Credentials: AES-256-GCM, data-key wrapped by ML-KEM-768 (FIPS 203).
  • Audit log: hash-chained & ML-DSA-65 signed (FIPS 204) — any rewrite is detected.
  • Resists harvest-now-decrypt-later.
